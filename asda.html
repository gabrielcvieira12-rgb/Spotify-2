Domine os comandos fundamentais para salvar seu progresso, publicar projetos no GitHub e colaborar profissionalmente com branches e Pull Requests.

01

Entendendo os Conceitos Básicos

Git (Local)

O Git é o sistema de controle de versão que roda na sua máquina. Ele funciona como uma "máquina do tempo" salvando o histórico do seu código em instantâneos (commits).

  • Funciona sem internet
  • Cria histórico de alterações
  • Gerencia branches locais

GitHub (Nuvem)

O GitHub é uma plataforma online de hospedagem para repositórios Git. É onde você compartilha seu código na nuvem e colabora com outros desenvolvedores.

  • Backup na nuvem do seu projeto
  • Pull Requests e Code Review
  • Portfólio público para empregadores

O Ciclo de Vida dos Arquivos no Git

1. Working Directory

Untracked / Modified

Arquivos alterados no seu editor (VS Code) que o Git ainda não está salvando.

2. Staging Area

Staged (`git add`)

A "área de preparação". Arquivos selecionados prontos para serem salvos.

3. Local Repository

Committed (`git commit`)

Alterações salvas permanentemente na história do seu repositório local.

4. Remote Repository

Pushed (`git push`)

Código enviado e sincronizado com o servidor do GitHub.

02

Configuração Inicial (Primeira Vez)

Antes de criar seu primeiro commit, você precisa se identificar no Git. Esses dados estarão vinculados a todas as alterações que você fizer.

git config --global user.name "Seu Nome"
git config --global user.email "seu@email.com"
Dica de Padrão Atual: É recomendado definir o nome da branch principal padrão como main com o comando: git config --global init.defaultBranch main
03

Subindo um Projeto Novo do Zero

Siga estes 6 passos para colocar qualquer projeto no GitHub

1

Inicializar o Git no Projeto

Abra o terminal dentro da pasta do seu projeto e execute:

git init

Isso cria a pasta oculta .git onde o histórico é mantido.

2

Criar o Arquivo .gitignore

Crie um arquivo chamado .gitignore para listar pastas/arquivos que NÃO devem ir para o GitHub (como senhas, chaves de API e a pasta node_modules).

# Exemplo de conteúdo do .gitignore node_modules/ .env dist/
3

Adicionar Arquivos à Staging Area

Adicione os arquivos para ficarem prontos para o commit. Use o ponto . para adicionar todos os arquivos.

git add .
4

Salvar a Versão Localmente (Commit)

Crie um instantâneo do projeto com uma mensagem clara sobre o que foi feito.

git commit -m "feat: commit inicial do projeto"
5

Conectar com o Repositório no GitHub

Crie um novo repositório no GitHub (botão "New Repository"), copie a URL do repositório e execute:

# Renomeia a branch principal para 'main' git branch -M main
# Conecta ao servidor remoto git remote add origin https://github.com/usuario/nome-do-repositorio.git
6

Enviar o Código para o GitHub (Push)

Agora envie seus arquivos locais para o GitHub!

git push -u origin main

O parâmetro -u serve para lembrar a origem. Nas próximas vezes, você poderá usar apenas git push.

04

Trabalho em Equipe com Branches

Como desenvolver sem quebrar o código de produção dos seus colegas

O que é uma Branch (Ramificação)?

A branch principal (main) representa o código em produção. Quando você vai criar uma nova funcionalidade ou corrigir um bug, nunca deve trabalhar direto na main. Você cria uma ramificação paralela (ex: feature/login).

Representação Gráfica:
main:
C1 ➔ C2 ➔ C3 (Produção) ➔ Merge Commit (C6)
feature:
└─ C4 (Login UI) ➔ C5 (Auth API) ──┘
Passo 1

Criar e Mudar para Nova Branch

Crie sua branch a partir da main atualizada:

git checkout -b feature/login

Ou use o comando mais recente: git switch -c feature/login

Passo 2

Publicar Branch no GitHub

Faça commits na sua branch e depois envie para o remoto:

git add . git commit -m "feat: add login screen" git push -u origin feature/login
Passo 3

Abrir um Pull Request (PR)

Vá no GitHub e clique em "Compare & pull request".

  • • Seus colegas revisam o código (Code Review).
  • • Testes automáticos são executados.
  • • Após aprovação, é feito o Merge para a main.

Como atualizar seu projeto local com o trabalho dos colegas?

Sempre puxe as novidades da main antes de começar uma tarefa nova:

git checkout main && git pull origin main
05

Como Resolver Conflitos de Merge

Não entre em pânico! Conflitos acontecem quando duas pessoas alteram a mesma linha.

1. Identificando os Marcadores

Quando o Git não consegue mesclar automaticamente, ele adiciona marcadores de conflito diretamente no código:

<<<<<<< HEAD (Suas alterações) const buttonColor = "blue"; ======= const buttonColor = "red"; >>>>>>> main (Alteração do colega)

2. Passo a Passo para Resolver

  1. 1 Abra o arquivo no seu editor (VS Code destaca isso automaticamente com botões "Accept Current Change" / "Accept Incoming Change").
  2. 2 Apague as linhas com <<<, === e >>> deixando apenas o código correto desejado.
  3. 3 Salve o arquivo, adicione na staging e finalize o merge:
git add . git commit -m "fix: resolve conflito na cor do botao"
06

Cheat Sheet de Comandos Rápidos

Guia de referência rápida para o dia a dia

Essencial
git status

Exibe o estado atual dos arquivos (modificados, staged, un-tracked).

Inspeção
git log --oneline

Mostra o histórico de commits de forma simplificada em uma linha cada.

Desfazer
git restore .

Descarta todas as alterações locais no diretório que ainda não foram salvas em Staging.

Branches
git branch -a

Lista todas as branches do projeto (locais e remotas).

Avançado
git stash

Guarda temporariamente alterações não salvas sem precisar fazer um commit.

Avançado
git stash pop

Restaura e aplica as alterações que haviam sido guardadas com o `git stash`.
